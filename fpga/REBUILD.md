# Rebuilding this design from a clean clone

Measured end to end on 2026-09-10 by cloning both repositories fresh and
building. **The result: a clean clone reproduces the shipping design exactly —
every utilisation figure identical, the packaged IP's 577 RTL sources
bit-identical — but only after a four-tier chain of generated inputs that was
not written down anywhere.** This file is that chain.

---

## Why the inputs are not simply committed

Three of the four tiers are `.gitignore`d, and for two of them that is correct
and must stay that way:

| Tier | Why it is not tracked |
|---|---|
| `tidelink/site.env` | Tool installs and vendor-IP roots are **per-machine facts**. It also resolves the Arm IP release path, and this repository is **public** — committing it would publish which Arm IP releases this lab holds. |
| `tidelink/deps/xhb500/generated` | 2626 files of **Arm XHB-500 generator output**, derived from licensed IP under the shared lab tree. Vendor collateral; not ours to redistribute. |
| `nanosoc-multicore-system/build_soc/rtl` | 254 files, a render of tracked YAML by a tracked generator. Regenerable, so a committed copy would be a snapshot that drifts. |
| `build/elab/*.f` | Generated by a tracked Python script. Same argument. |

So the deliverable is not the artefacts. It is a runnable path to them, and the
statement of what each step actually needs.

---

## The chain, in order

Every step is required. Step 1 is the only one that needs anything from outside
these repositories.

### 1. Site configuration — the only manual step

```sh
cp tidelink/site.env.example tidelink/site.env
$EDITOR tidelink/site.env
```

Set the EDA tool roots your host actually has, and:

    XHB500_IP_DIR   the `xhb500` directory of your licensed Arm DMA-350
                    release, normally resolved through $ARM_IP_LIBRARY_PATH.
                    `site.env.example` carries it as a commented placeholder.

**This is the step that stops a stranger.** Without the Arm licence there is no
XHB-500 IP, and no amount of git will supply it. `tidelink/set_env.sh:69`
refuses with a named variable rather than failing later, which is the right
behaviour.

### 2. Generate the XHB-500 bridge IP

```sh
source tidelink/set_env.sh          # generates deps/xhb500/generated if absent
```

Sourcing it runs the Arm generator over `deps/xhb500/configs/*.cfg`. Documented
at `tidelink/set_env.sh:10-12`; the output is `XHB500_GEN_DIR`.

### 3. Render the SoC RTL

```sh
make -C nanosoc-multicore-system soc
```

`nanosoc_gen` renders `build_soc/rtl` (254 files) from the tracked `sys_desc`
YAML. `flist/nanosoc_multicore.flist` has 11 references into it, so the flist is
unresolvable until this has run.

### 4. Flatten the flists

```sh
make elab                            # from the project root
```

Produces `build/elab/{soc_vcs,tidelink_vcs}.f`.

**`make elab` also runs a full VCS elaboration and takes a licence.** If you
only need the `.f` files, `flist/flatten_soc_flist.py` is pure Python and
reproduces `soc_vcs.f` byte-for-byte with no licence at all. The Makefile guard
that tells you to run `make elab` is misleading about that.

### 5. Package the SoC as IP

```sh
make -C tidelink/fpga package_eth_chiplet_ip
```

Produces `tidelink/imp/fpga/eth_chiplet_ip` — the whole SoC as packaged Vivado
IP, ~577 sources, which is what `IP_REPOS` in `fpga/design.mk` points at.

> **Always go through this make target. Never source the packaging TCL
> directly, and treat a retried or resumed packaging run as suspect.**
>
> `vivado_ip/nanosoc_eth_chiplet_filelist.tcl:146-148` deletes the v2 flist the
> Makefile wrote seconds earlier, and line 57 then falls back to the V1 list
> **silently** — exit 0, no warning. The result is a *different SoC* that
> compiles clean and reaches a bitstream: the whole GPIO-PHY generation is
> substituted, six PHY framing files vanish, and the include directory moves
> from `tidelink-phy` to `tidelink-gpio-phy`.
>
> **The tell is the source count.** V2 is `601 sources, 20 incdirs, 4 v2 shims`;
> V1 is `597 / 19 / 1`. `tidelink/fpga/Makefile:396` warns about this; the make
> recipe's regeneration step is the only thing preventing it.

`phc_ip` comes from `PHC_REPO_DIR`, which defaults to a `$HOME`-relative sibling
checkout with no submodule and no pinned sha — so that one IP is **not**
reproducible from this repository alone. It affects 9 files; the chiplet's own
PHC RTL resolves through the nested submodule and is fine.

### 6. Build

```sh
cd fpga
export KRIA_BOARD_FILES=<the XilinxBoardStore/boards/Xilinx dir inside your Vivado install>
make check          # contract complete?
make all            # flist -> package-ip -> bd -> synth -> impl -> bitstream
```

The Kria board files ship **inside the Vivado install**, not in the user `xhub`
store — the user store holds only `TUL/pynq-z2`, which is what made an earlier
pass wrongly report them missing.

## Checking where you are

```sh
make -C fpga bootstrap-status
```

Reports which tiers are present and names the command for the first one that is
not. It reads only — it generates nothing and takes no licence.

## What a clean clone gets wrong without this

Measured, from an actual fresh clone:

| Step | Exit | Cause |
|---|---|---|
| clone `--recurse-submodules` | 0 | 45 submodules, none failed |
| `make check` | 2 | `IP_REPOS` absent — tier 5 never ran |
| `make flist` | 2 | gated on the same check |
| `make synth` | 1 | gated-clock guard: 1 clock visible, 6 implementation-only |

The refusals were correct in both cases, and the second is worth noting: the
flow **stopped** rather than synthesising a design whose gated clocks would
silently not convert. Given this lab's history of clean checkouts building
different silicon without saying so, that is the behaviour the gates exist for.
