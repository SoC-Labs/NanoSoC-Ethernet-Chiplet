# 43 — Calibre DRC on `fp1505`, and the like-for-like against the shipping stream

[index](00-index.md) · [12 Calibre DRC](12-calibre-drc.md) · [28 DRC status and attribution](28-drc-status-and-attribution.md) · [39 `PO.R.8` resolved](39-po-r8-resolved.md)

**Measured 2026-08-18. This is the first Calibre DRC run over `fp1505`, and it was run
uncapped.** Until now the only DRC-shaped number for that build was Innovus's own 63
boundary records — a smoke test from a tool that has already disagreed *in sign* with
Calibre on this design.

---

## TL;DR — the two numbers, and the verdict

| | `fp1505` | shipping `full-20260814` |
|---|---:|---:|
| **raw** (what Calibre reported, what the foundry reproduces) | **837** | 837 |
| **post-waiver** (cell-scoped `PO.R.8`, applied by the census) | **146** | 146 |
| design-owned | 140 | 140 |
| — of which real **geometry** | **94** | 96 |
| — of which back-end density/dummy parents | 35 | 33 |
| — of which front-end density/dummy parents | 11 | 11 |
| vendor-memory | 697 (691 waived, 6 reported) | 697 (691 waived, 6 reported) |
| io-pad-abstract | 0 | 0 |
| core-only failing density windows | 6,159 | 6,149 |
| rulechecks with a non-zero count | 49 | 49 |

**Verdict: on Calibre's own reckoning `fp1505` is UNCHANGED versus the shipping stream.**
Same raw total, same post-waiver total, same design-owned total. Two design-owned
geometry results move out and two density-parent results move in. Nothing here is a
reason to prefer either stream, and nothing here is a reason to reject `fp1505`.

**And that is the finding, not a disappointment.** The thing `fp1505` fixes — four
rail-to-rail M5 VDD/VSS shorts — **is invisible to DRC**, demonstrated rather than
argued:

| build | Innovus `check_drc` total | of which `SHORT` | Calibre raw | Calibre post-waiver | Calibre design-owned |
|---|---:|---:|---:|---:|---:|
| `fp1505` | 63 | **0** | 837 | 146 | 140 |
| `full-20260814` | 68 | **4** (all `Special Wire VSS & Special Wire VDD`, M5) | 837 | 146 | 140 |
| `m5off5` | 67 | **5** | 837 | 146 | 140 |

Calibre DRC returns the *same three numbers* on a stream carrying four rail-to-rail
supply shorts and on a stream carrying none. Two overlapping same-layer rectangles merge
into one polygon that satisfies every width and spacing rule; the defect is electrical,
and it is why ERC-via-extraction, LVS and Voltus caught it and DRC did not. **Do not use
a DRC total to rank these builds.** Use it for what it does measure: back-end geometry.

## 1. The stream — located, identified, and confirmed to be the merged chip

```
ASIC/eth-chiplet/build/fp1505/outputs/nanosoc_eth_chiplet_pads.gds
  size    312,343,330 bytes  (298 MiB)
  mtime   2026-08-17 21:33:09 +0100
  sha256  12079d69cdaf1539520df10c1ae99558da59633d40b2d4d2060117cc5ce36e54
```

Search `ASIC/eth-chiplet/build/`, **not** `ASIC/genus-innovus/runs/` — a previous session
lost hours in the wrong tree root.

It is the merged, streamed chip and not an intermediate. `reports/nanosoc_eth_chiplet_pads_stream.rep`
records the generating command: `write_stream … -merge {8 macro GDS} -output_macros -unit
1000 -mode all`, on 2026-08-17 21:32:58. Three independent confirmations:

- **The macro GDS really is inside it.** 691 `PO.R.8` results fire from 22 named vendor
  memory-compiler leaf cells. A stream with the macros left as abstracts cannot produce
  them. Per-cell, all 22 counts are **byte-identical** to the shipping stream.
- **The layer inventory is complete and matches the shipping stream exactly.** An
  independent record-level census (`asic-flow-gds-layer-census`) finds the *same set* of
  layers in both, differing only in record counts, with identical text-record totals
  (349,274). 2,573 structures, 3,512,774 geometry records.
- **Same stream-out map.** `work/tech/gdsout.stream.map` is md5-identical across
  `fp1505`, `full-20260814` and `m5off5`, so the map is not a variable.

`fp1505` also shares the shipping build's *netlist*: its place-stage provenance names
`full-20260814/outputs/nanosoc_eth_chiplet_pads_gate_power.v`. Same logic, same map, same
merge set — the only variables are floorplan and route. That is what makes the comparison
below like-for-like.

**What `fp1505` is.** The `rf_32k` macro moved to y = 1505.60 (hence the name), at the
**default M5 start offset of 8** — the run log records `set M5_START_OFFSET 8`. It is a
*floorplan* variant, not an M5-offset variant.

## 2. The run

| | |
|---|---|
| rundir | `ASIC/genus-innovus/calibre_runs/drc_fp1505_20260818` (private; `calibre_runs` is gitignored) |
| tool | Calibre v2023.1_18.8, `-drc -hier -turbo 8` |
| deck | the project deck, assembled fresh from the read-only PDK by `make_project_deck.sh` — foundry rule bodies copied verbatim, body md5 verified against the foundry file |
| **result cap** | **`ALL` — UNCAPPED** |
| executed | 2026-08-18 10:18:16, real 331 s, CPU 1,399 s |
| rulechecks | **1,926 executed**, 3 `NOT EXECUTED`, 1,929 listed |
| results | **837** hierarchical, **4,428** flat |

Uncapped was reached through the flow's documented `DECK_HEADER` escape hatch: the header
was generated by `make_project_header.py` into the rundir, its one `DRC MAXIMUM RESULTS`
line changed from `1000` to `ALL`, and that header spliced. **No deck was edited, nothing
was written into the PDK, and no file in the source tree was touched.** The header is
generated vendor-derived material and stays in the gitignored rundir by design.

Reproduce:

```sh
cd ASIC/genus-innovus
RUNDIR=$PWD/calibre_runs/drc_fp1505_<date>
python3 scripts/calibre/make_project_header.py \
        --foundry-deck "$(…pdk_paths.sh drc-deck)" --output "$RUNDIR/header_uncapped.svrf.in"
sed -i 's/^DRC MAXIMUM RESULTS 1000$/DRC MAXIMUM RESULTS ALL/' "$RUNDIR/header_uncapped.svrf.in"
DECK_HEADER=$RUNDIR/header_uncapped.svrf.in \
  make drc GDS=../eth-chiplet/build/fp1505/outputs/nanosoc_eth_chiplet_pads.gds \
           DRC_RUNDIR=$RUNDIR DRC_CPUS=8
python3 ../../scripts/ci/drc_census.py $RUNDIR
python3 ../../scripts/ci/drc_census.py $RUNDIR --no-waivers
```

## 3. The four traps, answered with evidence rather than assertion

**1. A capped run looks clean, and the count-against-the-limit test does not catch it.**
Answered by removing the cap, not by testing for it. The summary header reads
`Maximum Results/RuleCheck: ALL`. `asic-flow-calibre-capped` over the summary returns
`ok`. There is no `Maximum result count of N exceeded` line and no `MAXIMUM RDB limit`
line anywhere in the summary.

> **A grep trap, recorded so nobody re-finds it.** `grep -c 'MAXIMUM RDB limit'` over
> `calibre_drc.log` returns **1** — in this run *and* in the reference run. It is the
> deck's own echo of our header's explanatory comment, which quotes that string. It is
> not a truncation. Match on the summary, not the log.

**2. An aborted operation counts as executed.** Checked explicitly. `operation aborted`
appears **zero** times in both the summary and the log. Three rulechecks report
`NOT EXECUTED` by name — `VAR.R.2`, `VAR.R.3`, `VAR.R.5` — the same three as every other
run on this design. They are counted as *not measured* below, never as zero. The
summary's runtime-warnings section is **identical, line for line**, to the shipping
stream's: 17 warnings, no errors.

**3. The gate is blind to layers the deck maps no rule to.** Still true, unchanged, and
it applies to this number as much as to any other. The die-outline annotation that fills
all four corner keep-outs sits on a layer the deck maps no rule to, so it reads as
nothing — see [35](35-drc-layer-map-blindness.md). Say *"clean of manufacturing layers"*,
never *"nothing there"*. Nothing in this run re-measured that, and nothing in this run
changes it.

**4. The stream is not self-contained.** §5 is the classification this demands. No
unmeasurable check is reported as a pass anywhere on this page.

## 5. Measured / unmeasurable — every rulecheck classified

Classification is anchored to a **measurement of what the stream contains**, not to
assumption. A record-level layer census of `fp1505`, resolved through the derived
stream-out map and split by owning structure, shows:

- **M1–M9 and VIA1–VIA8 carry geometry in the top cell** — our routing, our power grid.
  Measured.
- **Front-end layers (diffusion, poly, contact, well, implant, threshold and SRAM
  markers) carry geometry ONLY inside the eight merged vendor-macro hierarchies.** The
  top cell has none. The standard-cell and IO/pad masters have essentially none.
- **Passivation, pad-opening, under-bump, seal-ring and every device-marker layer carry
  no geometry at all**, anywhere in the stream.

That gives four honest classes, machine-counted over all 1,929 rulechecks in the summary:

| class | rulechecks | results | what a zero from it means |
|---|---:|---:|---|
| **MEASURED — back-end** (metal, via, their density and dummy parents) | 814 | 133 | a real result about what P&R produced |
| **MACRO-ONLY — front-end** (diffusion/poly/contact/well/implant/VT/SRAM) | 465 | 702 | a real result *about the vendor macros only*; **blind over every standard cell and IO cell in the design** |
| **UNMEASURABLE — input geometry absent** (passivation, pad opening, under-bump, seal ring, latch-up, ESD, device markers) | 331 | 2 | **NOT CHECKED.** Never quote as clean |
| **UNMEASURABLE — no fill / marker layers absent** (dummy-fill and marker families) | 305 | 0 | **NOT CHECKED** |
| VACUOUS — "layer must not be drawn", and we draw none | 11 | 0 | true but content-free |
| **NOT EXECUTED** — `VAR.R.2`, `VAR.R.3`, `VAR.R.5` | 3 | — | **not measured**, by the tool's own word |
| **total** | **1,929** | **837** | |

Three consequences, stated so they cannot be skipped:

1. **The design-owned 140 is a FLOOR, not a total.** No standard-cell, IO-driver or
   bond-pad layout exists in this stream, so a rule that would fire against cell-internal
   geometry cannot fire at all. Read `design == 0` as *"clean in the layers we actually
   have"*.
2. **The 2 results in the unmeasurable bucket are `DRM.R.1` and `ESD.WARN.1` — deck
   warnings, not ESD or latch-up results.** `LUP.* = 0` remains NOT CHECKED: pad
   recognition needs passivation geometry the stream does not carry, and every latch-up
   expression terminates in diffusion the IO cells do not have. Unchanged from
   [28](28-drc-status-and-attribution.md) §6, and re-confirmed by the layer census above.
3. **Antenna was not run on `fp1505` and is not in these 1,929.** It is a separate deck.
   The standing figure — 714 rulechecks, 0 results — was measured on an *earlier* stream
   and is a **NULL RESULT**, not a pass: it is the number you get when the gate-area
   inputs are absent. Do not carry it forward to `fp1505` as a clean antenna result.
   Neither BND nor LUP was run on `fp1505` either.

## 6. The M5-offset question — it did not move, and this is the third measurement saying so

`fp1505` runs the **default offset 8**, so it is not itself an offset variant. The offset
pair remains `full-20260814` (F=8) against `m5off5` (F=5):

| | F=8 | F=5 | moved? |
|---|---:|---:|---|
| raw | 837 | 837 | no |
| post-waiver | 146 | 146 | no |
| design-owned total | 140 | 140 | no |
| design geometry | 96 | 98 | +2 — **worse** |
| back-end density parents | 33 | 31 | −2 |
| core density windows | 6,149 | 6,219 | +70 — worse |

**The M5-offset family has not moved, and no offset is worth running.** The offset
redistributes between rule classes (`M4.S.2.1` 28 → 7 and `M4.S.1` 12 → 0 leave;
`M5.A.2` 2 → 27 and `G.4:M4i` 2 → 14 arrive) and never reduces the total. `fp1505` adds
a third, independent confirmation from a different direction: a **floorplan** change at
fixed offset also holds the raw total at 837 and the design total at 140 while moving the
composition. Three streams, three different geometries, one number.

That coincidence is worth naming: **837 arriving three times is not evidence that nothing
changed.** The composition moved every time — geometry 94 / 96 / 98, back-end density
parents 35 / 33 / 31 — and the two halves happen to cancel. Quote the composition, not the
total.

## 7. What this page does not say

- It does **not** say `fp1505` is DRC-clean. It is not: 140 design-owned results and
  6,159 failing core density windows.
- It does **not** say `fp1505` is better than the shipping stream on DRC. It is the same,
  within a two-result reshuffle that is below the noise of a re-route.
- It does **not** say the two streams are equivalent overall. They are not — `fp1505` is
  free of the four rail-to-rail M5 supply shorts, and that difference is real, agreed by
  four independent tools, and **structurally invisible to the number on this page**.
- It does **not** re-open `PO.R.8`. The 691 reproduce exactly, per cell, on a second
  stream — which is a stronger reproduction than [39](39-po-r8-resolved.md) had, and it
  changes nothing about the conclusion there.
